# Bare-metal HolyC REPL

Interactive HolyC on RISC-V (UART console). Language surface matches a source file: functions,
classes, globals, `#define`, statements. Statements compile and run immediately; the
result prints in hex unless you use `Print` / `"fmt", args;`.

Default seed MMIO (`MEM_*` in `MemMapSelected.hc`, regenerated by `make -C templeos-riscv
syncconfig`) matches the active Kconfig board — CI default is **virt**. Flip boards with
`defconfig-*`, then rebuild with `make hc-repl` if you need the REPL to follow —
[PLATFORM.md](../templeos-riscv/PLATFORM.md) / [KCONFIG.md](../templeos-riscv/KCONFIG.md).

## Run

**One true command — classic UART HolyC REPL** (no C guest; WinMgr/FB Term is a different path):

```bash
make hc-repl          # same as: make repl-holyc
qemu-system-riscv64 -M virt -m 128M -bios none -kernel build/repl-holyc.elf -nographic
# Expect: boot banner → Help → prompt "> "  (type 1+2; → ans=0x…=3)
```

Aliases: `build/hc_repl.elf` ≡ `build/repl-holyc.elf`. Smoke/regression:
`make hc-repl-smoke` / `make repl-holyc-regression`. Split boot:
`make bootloader-repl` / `bootloader-smoke`. Guest Cmp converge (A2):
`make repl-cmp` → `build/repl-cmp.elf`. See [SELF_HOST.md](SELF_HOST.md).

Legacy C guest (`worry_dream_repl.c`) is **deleted**; `make repl-smoke` /
`repl-regression` exit with a redirect to the HolyC targets above.

Memfs seeds (`Lib/print.hc`, `Tutorials/…`, …) embed into the HolyC AOT guest
via `bootstrap/hc_repl/` (`gen_embed.py`). Bare names (`Run("print.hc")`,
`Cat("boot.hc")`) still resolve while basenames stay unique. After editing
`bootstrap/seed/*.hc`, rebuild with `make hc-repl` (optional seed-concat helper:
`make repl-blob`).

### Memfs layout

```
/Home          user files (hello on the AOT guest)
/Tmp           scratch
/Boot          boot.hc, start.hc, trap/timer, MemMapSelected, …
/Lib           print, str, fs, uart, mem, dir, files, run, …
/Apps          Vi/Edit/Ed, Funs, Callers
/Asm           asm_doc, asm_complete (disasm.hc seed unwired on thin REPL)
/Doc           man, man_topics, tutorial
/Doc/Datasheet ds_uart.hc, ds_csr.hc, …
/Tutorials     A01_*.hc, B*.hc, C*.hc
```

`Dir;` lists the current directory (subdirs as `name/`). `Cd("Tutorials");` `Pwd;`
(`Pwd` and `Cd` log print `::/Tutorials/` — TempleOS boot-root form; `Cd` also accepts
`::/Tutorials`, `A:/Home`, `~/Work`). `MkDir("Home/Work");` (alias of TempleOS `DirMk`).
Kernel/Drv is not in this REPL tree. Full dual-namespace map: [PATHS.md](PATHS.md).

Compile errors print as `file:line:col: error: …` (host `holyc-riscv` and the UART REPL).
`ErrGo;` opens the preferred editor on the last error site.

From repo root:

```bash
make hc-repl-smoke           # alias: repl-holyc-smoke
make repl-holyc-regression   # primary HolyC honesty gate (CI)
make repl-cmp-smoke          # A2: guest Compiler_RV ExePutS UART loop
make bootloader-smoke        # HolyC split-boot product path
```

See [tests/REGRESSION.md](../tests/REGRESSION.md) for what “PASS” must mean. Local emulator

## Boot welcome and history

On start, `boot.hc` prints `[boot] HolyC primitives loaded…` then `Help;` — a short
capability overview (eval, editors, Man, MemMap/Regs, asm, timer, files, keys, soft
`Reset;`). Type `Help;` again anytime. To leave a QEMU virt session cleanly, use guest
`Quit;` / `Exit;` (SiFive test PASS @ `MEM_TEST` → host exit 0); soft `Reset;` only
re-enters Boot. Prefer guest Quit over host-emulator key sequences as product UI.

Readline history is **preloaded** (oldest→newest) so **Up** walks demos first:

`Help;` → `1+2*3;` → `Man("Clint");` → `Man("Print");` → `Src("Dir");` → `MemMap;` →
`Regs;` → `Dir;` → `Cat("boot.hc");` → asm/`Reg("a7")` → `Fmt("boot.hc");`
(`Uf`/`U` are **not** live on thin `repl-holyc` yet — seed `disasm.hc` unwired; see [REPL_FUNS.md](REPL_FUNS.md).)

(History seed: `RlHistSeed` in `bootstrap/seed/readline.hc`; banner in `bootstrap/seed/boot.hc`.)

**Up/Down** recall whole **compile units**, not individual physical lines: a multi-line
function entered across several Enters is one history entry (embedded newlines). While a unit
is still open (unbalanced `{`/`(`), the prompt stays on **`... `** continuation instead of
printing a fresh **`> `** until braces/parens balance and the unit compiles.

## Inline `asm{}` (RISC-V)

Unlabeled `asm{}` on the host/REPL path emits raw RV via `TryAssembleRiscV`. Notes:

- No `subi` — use `addi rd, rs, -imm`.
- `sub` is R-type only (`sub rd, rs1, rs2`).
- ABI names `a0`–`a7`, `s0`–`s11`, … work.
- CSR ops accept numeric immediates or names from `csr.hc` (`mstatus`, `mepc`, …).
- Tab inside `asm{}` completes opcodes / registers / CSR names (REPL C readline + editor `CompTab`; tables in `bootstrap/seed/asm_complete.hc`).
- Tab outside `asm{}` also completes `#define`s: CompAdd catalog (`MEM_*`/`UART_*`/…), session `#define` names (`DefRegister` on thin `repl-holyc`), and host `define_table` when published (legacy).
- Guest destination assembler is `Compiler/Asm_RV.HC` (`CMP_RV_ASM`).

```holyc
asm {
  li a7, 20
  addi a7, a7, -4
};
Regs;
```

More: [COMPILER_RV.md](../templeos-riscv/COMPILER_RV.md) (asm section).

## Ctrl-C interrupt

| Context | Behavior |
|---------|----------|
| At `>` prompt | Clears the draft line, prints `^C` / `Interrupted`, stays at the prompt |
| During eval (busy `for(;;)`, …) | UART RX IRQ (PLIC #10 on the default virt-style map) sets a break flag; trapvec aborts the eval — `Interrupted` back to `>`, or `throw('Break')` into an active `try`/`catch` |
| `Break;` | HolyC helper: `throw('Break')` (same exception code) |

`TrapInit` enables 16550 RX IRQ + PLIC + `mie.MEIE`, so a normal `wfi` **does** wake on Ctrl-C. If you clear `mstatus.MIE` or `mie.MEIE` (or never call `TrapInit`), bare `wfi` will not see Ctrl-C until a timer or other IRQ wakes the CPU. Editors are not break-armed: `^C` is still a keystroke there.

### What the interrupt source number costs you (2026-09-29)

The break depends on one number that is not the same on the board and in the emulator, and that
difference hid the whole path from testing. UART0 is PLIC source **39** on the FU740 and source
**4** on QEMU's `-M sifive_u`. The HiFive Unmatched REPL image is built with 39, so under the
harness its RX interrupt was enabled on a line QEMU never raises: the break could not fire, and
nothing noticed, because no gate had ever asked it to. `make repl-unmatched-ctrlc-smoke` builds a
QEMU twin on source 4 and wedges the REPL in `while(1)`, sends `^C`, then asks it to evaluate
`2+3`. Both halves are asserted, because they fail for different reasons: the recovery line proves
the interrupt reached the trampoline, and the answer after it proves the prompt is still listening.

Two real defects fell out of writing that gate:

- **The recovery path returned with the RX interrupt still enabled.** The trampoline lands inside
  the `if (RVTrapRecoverArm())` branch, skipping the `RVUartIrqOff` that follows the evaluation —
  so after any break or fault the handler kept taking every keystroke into the runtime's own ring,
  which only the normal path drains. The prompt came back and was deaf. Both REPL loops
  (`Kernel/RVWinSerial.HC` and the exepubs demo) now turn it off and drain on the way out.
- **The debugger pane drew a fault that never happened.** A break publishes no trap snapshot, so
  the pane rendered an all-zero frame and decoded `mcause` 0 as `insn address misaligned`. It is
  now skipped for `cause < 0`, which says `^C — interrupted` instead.

`uart_hw_drain` clears `mstatus.MIE` for the LSR→RBR loop so a nested IRQ (UART or the break-poll timer) cannot empty the FIFO between the data-ready check and the read — otherwise QEMU’s 16550 returns the stale last `RBR` and the ring gets a duplicate key (`aa` per keystroke). Masking only `mie.MEIE` left the timer free to re-enter drain. Check: `make repl-uart-echo-pty`.

## Console keys (win_vt DocTerm over the UART)

The Term window keeps every line it printed; the serial line editor understands the
VT cursor keys so you can read back through it:

| key | effect |
|-----|--------|
| PgUp / PgDn | page the Term window back / forward through its history |
| Up / Down arrow | one line back / forward |
| Home / End | oldest line / back to the live bottom |
| any new command | jumps back to the live bottom |

The terminal is asked for its size at boot (`CSI 18 t`); a real terminal answers and the
desktop is laid out at that size, a pipe or dumb terminal keeps the `RV_VT_COLS`/`RV_VT_ROWS`
defaults from `tests/exec/aot/win_flag_vt.hc` (80×24). Pasted lines up to 1023 bytes are
taken intact (the RX interrupt ring, not the 16-byte FIFO, buffers them).

## Debugger surface (win_vt)

| call | what |
|------|------|
| `Disasm("Name")` / `Uf("Name")` | disassemble a function (hash size when known, else to `ret`) |
| `U(addr, n=28)` / `DisasmAt(addr, max, end)` | raw window at an address |
| `UA(addr, n=28)` | assemblable source you can paste back into `asm { … }` |
| `FnAddr("Name")` | code address of a function or Kernel export |
| `Bp(addr)` / `Bp` | plant an `EBREAK` at a code address / list breakpoints |
| `BpClr(addr)` / `BpClr` | restore one / all |
| `PassTrace(bits)` | dump the compiler's ICs for every following line (`PassTrace(0)` stops) |

A breakpoint hit returns to the prompt ("*** breakpoint at … <Name+0x..>"), restores every
breakpoint, and abandons the line — there is no `Step` yet. `Bp` writes 4 bytes, so a
breakpoint on a compressed (2-byte) instruction also covers its neighbour until cleared.
Faults do the same (mcause/mepc/mtval/ra line); `crash` drops into the monitor for `md`/`bt`.


## Running it: `make tos`

`make tos` (alias `make kernel-tos`) boots a **clean interactive TempleOS/RISC-V** —
the real HolyC ExePutS REPL and DolDoc desktop presented to your terminal as ANSI over
the UART, with NO scripted self-test demo. It builds `build/exec/win_tos.elf` (the same
kernel + compiler + DolDoc as `kernel-vt-holyc`, differing only in the link-time flag
unit `tests/exec/aot/win_flag_tos.hc`, which sets bit 32 = "clean boot"), sizes the VT to
your terminal, and drops you at the `> ` prompt:

    2+3;                         # arithmetic
    "hi\n";  I64 i=7; i*6;       # HolyC statements
    F64 f=2.0; Sqrt(f);          # F64 math
    Cat("A:/Doc/VtDemo.DD");     # render a DolDoc file (colour + links interpreted)
    Dir;                         # list the RAM filesystem
    q                            # quit (or Ctrl-A then X)

The runtime library functions ported for the REPL (MAlloc/StrPrint/FilesFind/FileRead/
Now/…) and the CDirEntry/CDateStruct types are all callable here.

**Real disk on B:.** `make tos` builds a RedSea disk image (`build/exec/tos_disk.img`)
from the full stock `tos/Doc` tree plus a few Demo programs and attaches it as a
virtio-blk device. The clean boot mounts it as `B:` (via `RVMountVirtioDisk`), so every
stock TempleOS document is browsable — `Cat("B:/Doc/Welcome.DD");`,
`Cat("B:/Doc/DolDocOverview.DD");`, etc. `A:` remains a RAM disk for scratch files.
Without the disk, the mount is a no-op and `A:` still works.

## Browsing DolDoc links with the cursor

The desktop windows are DolDoc documents, and their links/trees/buttons are now
**selectable by the cursor** in the VT console:

* **Tab** cycles focus among the windows (`RVWinFocusNext`). Tab onto a browsable
  document — the **HOME.DD** window, or a window opened by following a link — and the
  arrows switch from Term scrollback to *link selection*.
* **↑/↓** (and ←/→) move the selection between the clickable entries (`RVDocSelMove`);
  the selected link paints fg/bg-**inverted** so you can see it, and the window scrolls
  to keep it in view.
* **Enter** activates the selected entry (`RVDocActivate`): an `FI:` link opens its
  target document in a new window (and focuses it, so you can keep browsing), a `$$TR$$`
  tree toggles collapse, a check-box flips.
* **Tab** again returns to the Term, where the arrows scroll history and Enter evaluates
  HolyC as before. The Term/Adam REPL consoles are never link browsers.

Implementation: `RVDocSelMove`/`RVDocSelClickable` (Kernel/RVDoc.HC) walk the CDoc entry
ring; `RVWinDocFocusIsNav`/`RVWinDocFocusSelMove`/`RVWinDocFocusActivate`
(Kernel/RVWinMgr.HC) gate the behaviour on the focused window's kind and drive the
scroll; the escape decoder (`RVWinSerialEscKey`) and `RVWinTermPutChar`
(Kernel/RVWinSerial.HC) route the keys. The selected-entry highlight is in
`RVDocDrawWin`.

## Searching the doc tree: `find`

`Find("needle");` greps the mounted doc tree (`B:/Doc`, else `A:/Doc`) for a substring and
opens the hits as a **browsable** DolDoc window — one `$$LK$$` per matching file, written to
`A:/Doc/_Find.DD`. Tab onto that window, arrows select a result, Enter opens it
(disk-backed). Caps at 40 matches / 200 files. It is a real HolyC function planted through
the compiler (`RVExePubFunNew("Find",…)` in Compiler/RVExePubs.HC → `RVWinSoftFind` in
Kernel/RVWinSerial.HC), not a dispatch bareword — you call it like `Cat`/`Dir`, and the
results inherit the cursor nav for free. `Tasks;` lists the desktop windows and their task
bindings the same way.

## Editing files: `ed`

`Ed("file");` opens a full-screen-lite text editor in its own window (`RV_WIN_KIND_EDIT`):
the file loads into a CDoc, printable keys insert, Backspace deletes, Enter splits a line,
the arrows move the cursor (↑/↓ by line, ←/→ by run), **Ctrl-W** writes the file, and
**Tab** leaves back to the Term. The caret tracks the insertion point.

Primitives reused: `DocEdInsChar`/`DocEdBackspace` (edit), `RVDocEdMove` (cursor),
`RVDocEdExtractText` (serialize entries → plain bytes), `FileWrite` (save). `Ed`, like
`Find`/`Tasks`, is a compiler-callable HolyC function (planted in Compiler/RVExePubs.HC),
not a dispatch bareword. Verified on `make tos`: `Ed("A:/Doc/scratch.DD");`, type two lines,
Ctrl-W → `wrote … (24 bytes)`, text renders live.

**Limitations (by design, for now):** cursor movement and insertion are at run/line
granularity, not intra-run — you compose top-to-bottom and correct with Backspace, rather
than positioning inside an existing word. Saving extracts plain text, so a `$`-markup
`.DD` is flattened; edit plain files (HolyC source, notes) or `A:` scratch, not stock
`B:/Doc` documents. No undo UI.

## The write-a-program-and-run-it loop

The console closes the loop end to end, all through the guest compiler:

    Ed("A:/prog.HC");                 # opens the editor window
    I64 s=0,i;                        # type your program
    for(i=1;i<=5;i++) s+=i;
    Print("sum=%d\n",s);
    <Ctrl-W>                          # save
    <Esc>                             # leave the editor, focus the Term
    #include "A:/prog.HC"             # compile + run it → sum=15

`Esc` in the editor focuses the Term (the window stays open — Tab back to keep editing).
Verified on `make tos`: the program above saves (55 bytes) and prints `sum=15`.

## Exploring the RISC-V machine

The console carries a RISC-V exploration toolkit (Kernel/RVExplore.HC, planted as HolyC
functions — call them like any other):

    AsmList;              # the documented asm{} mnemonic catalog (137 entries)
    AsmDoc("addi");       # one mnemonic: template / encoding / imm range / notes
    MemMap;               # QEMU-virt physical map (CLINT/PLIC/UART/DRAM + image regions)
    Mstatus;  Mcause;     # read + decode the trap CSRs
    Csr("misa");          # read + decode ANY M/S CSR (misa -> RV64 ext:A C D F I M S U)
    Csr("mtvec");         # ... mie mip mepc mtval satp sstatus scause ...
    Uptime;               # cycle / time / instret counters

Plus the debugger surface already present: `Disasm`/`U`/`Uf`/`UA` (disassemble),
`Bp`/`BpClr` (breakpoints), `Reg`/`Regs`, and the crash-shell `md`/`mw`/`csrs`/`bt`.

**"What compiles" ≠ "what can be assembled."** The HolyC compiler backend emits
`I + M + A + F/D`; the inline `asm{}` assembler accepts a smaller set (`I + M + A + Zicsr`,
no float, no branches/jumps). `AsmList`'s footer says so, and `asm{ <ins> };` at the prompt
is the live test of what actually assembles. The full three-way picture (assembler vs
disassembler vs codegen, with the drift between them) is in `docs/RISCV_INVENTORY.md`.
