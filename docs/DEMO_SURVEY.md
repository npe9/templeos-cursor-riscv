## Levels

| level | meaning |
|---|---|
| **L0-FAIL** | does not compile against the RV kernel — a symbol the port lacks |
| **L1-TRAP** | compiles and links, then FAULTS |
| **L1-HANG** | runs but does not finish inside the window (some just print a lot) |
| **L1-OK** | loads into a real image, boots, runs its own top-level code, reaches the end |

**What L1 does not claim:** that a program does anything useful. Only four are driven with
scripted input and checked for a real response — Halogen, MassSpring, BattleLines and Lines
(`make kernel-game-{input,mouse,scanchar,lines}-smoke`). Everything else is untested above
"it runs".

Two harness mistakes had to be fixed before these numbers meant anything, and both had been
reported as kernel bugs first:

1. 141 demos ended in an unguarded autorun, so INCLUDING one ran it at load. Now guarded with
   `#ifndef RV_NO_DEMO_AUTORUN`.
2. The kernel has to be booted BEFORE the demo is included — a demo's top-level statements run
   at load and many print, and `PutS` dereferences `Fs`. Booting inside `main()` made **18 of
   32 traps** fault in `PutS` before `main` ran. Fixing that alone took L1-OK from 107 to 123.

### The symbols, ranked

`best_score` is one bug, not thirteen. Eleven games and two templates open with

```
RegDft("TempleOS/FlapBat","F64 best_score=9999;\n");
RegExe("TempleOS/FlapBat");
```

In TempleOS the top-level `RegDft` RUNS while the file is being compiled, and compiling its
string is what declares `best_score`. An AOT compiler never runs it, so every later mention is
undefined. Teaching the host compiler to parse that string as declarations is the single

## Does not finish (L1-HANG)

Re-run at 40s with the whole serial log read, which splits them three ways.

**Waiting for a key that never comes** — the harness gives them no stdin. Not a port bug; they
stop exactly where a person would be asked something.

| program | last thing it printed |
|---|---|
| `Demo/Define.HC` | `Spanish(y or n)? ` |
| `Demo/Progress.HC` | `PRESS A KEY` (it got through two of the four Mains) |
| `Demo/InFile/InPopUp.HC` | `PopUp #1:1` |

**A named compiler gap** — `Carry` is not implemented on RISC-V.

`Demo/Carry.HC` printed 470,109 lines in 40s and never advanced:

```
0000000000000000 9800000000000000
0000000000000000 9C00000000000000
0000000000000000 A000000000000000
```

`hi` is the left column and it never leaves zero. `BigCnt` is `lo+=1<<58; hi+=Carry;` and loops
`while (hi<0x10)`, so a `Carry` of zero is an infinite loop. `Carry` is declared
`public _intern IC_CARRY I64 Carry();` in `Kernel/KernelB.HH`, and `IC_CARRY` has no case in
`Compiler/OptPass_RV.HC`; `host/parser.c` skips the `IC_CARRY` token and leaves `Carry` an
ordinary undefined function, so it loads as an unresolved import that returns 0. RISC-V has no
carry flag, so implementing it means the code generator emitting `sltu` after each add in any
function that names `Carry` — worth doing, but it is one demo.

**Silent — nothing printed at all.** Each of these needs its own look.

- `Demo/Games/TheDead.HC`
- `Demo/Graphics/Doodle.HC`
- `Demo/Graphics/Speedline.HC`
- `Demo/Graphics/Symmetry.HC`
- `Demo/MultiCore/Lock.HC` — `JobQue` onto core 1, and 0x1000000 iterations four times over
