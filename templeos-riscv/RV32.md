# RISC-V 32-bit (RV32) port plan

**Status: planning + Kconfig ARCH stub; HolyC emit not started.** `ARCH_RISCV32`
exists as a derived Kconfig bool when `ISA_RV32*` is selected (headers /
`qemu-system-riscv32` choice only). Host `holyc-riscv` and guest `Compiler_RV`
remain **RV64 / LP64**. OpenTitan plat smoke is still the **RV32 asm harness**;
HolyC drivers `RVUartIbex` + `RVTimerIbex` are ready for the map.

**Exact emit blockers (refresh when anything moves):**

1. `host/compiler.c` — all memory ops / frames use `ld`/`sd` and 8-byte stack
   slots (search `3<<12` load/store width).
2. `host/parser.c` — pointer / `I64` `TypeSize` assumed 8.
3. Guest `Compiler/Back*_RV.HC`, `Asm_RV.HC`, `RISCVRegs.HH` — XLEN=64.
4. No `--target rv32` / `HOLYC_XLEN` switch on the host binary yet.

**Smallest stub that unblocks OpenTitan beyond asm:** host ILP32 emit for the
`kernel_plat_demo.hc` subset (UART + Ibex timer reads) on `qemu-system-riscv32
-M virt` first, then retarget the OpenTitan link script — see §10 and
[DRIVERS.md](../docs/DRIVERS.md).

Today the tree is **RV64 / LP64** end-to-end. The `opentitan` defconfig already
selects `qemu-system-riscv32` — that is **board scaffolding** (tiny DRAM map +
Ibex UART/timer HolyC drivers), **not** an RV32 HolyC ABI or emit path.

## 1. Goals / non-goals

### Goals (ordered)

1. **P0 bring-up:** a tiny AOT HolyC program prints over UART on
   **`qemu-system-riscv32 -M virt`** (same 16550 / CLINT / PLIC map as RV64
   virt).
2. **P1 language slice:** host `holyc-riscv` emits correct **ILP32** codegen for
   the exec-oracle / REPL subset already trusted on RV64 (ints, calls, pointers,
   loops) — with **`I64` as a real 64-bit type** via soft ops / register pairs.
3. **P2 kernel slice:** a reduced `Kernel_RV32` (or gated `Kernel_RV`) boots,
   traps, and returns from a timer/UART path on RV32 virt with enough RAM
   (default QEMU virt memory — **not** OpenTitan’s 128 KiB).
4. **P3 guest compiler:** `Compiler_RV32` or dual-emit `Compiler_RV` that
   produces RV32 machine code for `ExePutS` / guest `Cmp` (mirror RV64 phase3
   philosophy in [COMPILER_RV.md](COMPILER_RV.md)).
5. **P4 OpenTitan / Ibex (separate track):** a **tiny profile** (UART hello +
   maybe a few KiB of HolyC) once RV32 virt works — **not** a TempleOS host.

### Non-goals (near term)

- Full TempleOS / Adam / DolDoc / graphics parity on RV32.
- Replacing RV64 as the CI default or “supported” platform.
- Fitting `Kernel_RV.PRJ` AOT blobs (~1 MB class) or `Compiler.BIN` (~1.1 MB)
  into OpenTitan’s **128 KiB** DRAM.
- Binary compatibility with existing RV64 `.BIN` / exec-harness ELFs.
- Growing `bootstrap/hc_repl/jit.hc` for RV32 (same freeze rule as RV64 —
  interactive compile destination remains guest `Cmp` / `ExePutS`).
- Dual-maintaining a second copy of `host/parser.c` / `host/compiler.c`.
- Shipping RV32 soft-float / RV32D as a first milestone (integer + soft `I64`
  first; `F64` after).
- Making `holyc-riscv --fmt` XLEN-aware as a port blocker (fmt is AST/style;
  keep RV64 fmt green; do not invent an RV32-only formatter fork).

## 2. First target: virt-rv32, not OpenTitan

| Target | Why |
|--------|-----|
| **`qemu-system-riscv32 -M virt`** | Same MMIO as RV64 virt (16550 @ `0x10000000`, CLINT, PLIC). Drivers already HolyC (`Kernel/Drv/`). DRAM is large. Isolates **ABI/codegen** from **tiny-RAM**. |
| **OpenTitan** | Valid *later* stress test (Ibex UART + timer HolyC drivers, 128 KiB budget). Wrong as the first ABI proving ground. Today: `configs/opentitan_defconfig` + `UART_IBEX` + `HAS_IBEX_TIMER`; plat smoke = RV32 asm. |
| **sifive_e (rv32)** | ~16 KiB DTIM — worse than OpenTitan for anything beyond bare asm hello. |

**Recommendation:** when implementation starts, add **`ARCH_RISCV32` +
`virt_rv32_defconfig`**. Keep `opentitan` experimental and explicitly “tiny
profile only.” Do **not** retarget `make kernel-plat-smoke` away from RV64 virt.

Kconfig today: `ARCH_RISCV32` is derived from `ISA_RV32IMAFDC` / `ISA_RV32IMA`
(headers / QEMU binary only). HolyC emit ignores it until §10 patch 3.
`CONFIG_QEMU_SYSTEM` defaults to `qemu-system-riscv32` when
`PLATFORM_OPENTITAN` or `ARCH_RISCV32`.

## 3. ABI: ILP32 + wide HolyC `I64`

### Current (RV64)

- **LP64:** pointers and `I64` are 8 bytes; host emit uses `ld`/`sd`, 64-bit
  immediates; args in `a0`–`a7`, return in `a0`.
- Host parser hard-codes pointer width as 64-bit in places (e.g.
  `host/parser.c` — “Pointers are 64-bit addresses”; `TypeSize` maps
  `RT_I64`/`pointers` to 8).
- Guest `Compiler/Back*_RV.HC`, `Asm_RV.HC`, `RISCVRegs.HH` assume XLEN=64.
- Hand asm (e.g. `bootstrap/seed/trap.hc`, `Kernel/KUtilsRV.HC`) uses `ld`/`sd`.

### Proposed RV32 default: **ILP32 + soft/wide `I64`**

| Type | Size / align | Notes |
|------|----------------|-------|
| `I8`/`U8`/`I16`/`U16`/`I32`/`U32` | natural | Unchanged |
| **Pointers / `U8 *`** | **4 / 4** | ILP32; `sizeof(U8*)==4` |
| **`I64` / `U64`** | **8 / 8** (or 8/4) | Keep TempleOS meaning; **two GPRs or libcalls** |
| `F64` | 8 | Soft-float or RV32D later; not P0 |

**Rationale:** TempleOS HolyC is `I64`-centric. Shrinking `I64` to 32-bit would
fork the language. Keeping `I64` wide while shrinking pointers matches normal C
on RV32 and is the least-wrong TempleOS mapping.

### Rejected / deferred

| Option | Verdict |
|--------|---------|
| **I32-centric subset** (`I64` = `I32`) | Throwaway demo only — not TempleOS/RV |
| **“LP64 on RV32”** (8-byte pointers, high half zero) | Wastes RAM/regs; avoid |
| **Soft-float as P0** | Defer |

### Calling convention (freeze in P0)

Follow **ILP32** RISC-V psABI where practical:

- Args in `a0`–`a7`; 64-bit values in **even–odd** pairs (`a0`/`a1`, …) —
  same idea as GCC `-mabi=ilp32` for `long long`. **Pick one scheme in P0 and
  freeze it.**
- Stack aligned to **16 bytes** even though XLEN=32.
- Trap frame: saved GPRs are **32-bit slots** (see §6) — not today’s 8-byte
  `sd` layout.

### Struct / TempleOS layout hazard

Pointer members shrink → **offsets change**. Audit patterns that stuff pointers
into `I64`, `INVALID_PTR`, hash entries, `CTask *`, DolDoc pointers, and
bootstrap **host slots** that today are 8-byte strides (e.g. REPL fixed-area
slots under `0x87001xxx`).

Existing **AOT BINs and `Compiler.BIN` are RV64** — never `Load` them on RV32.

**Gate before Kernel_RV32:** layout ABI checks (`#assert`-style or dual-width
size macros) for a handful of critical structs under both widths.

## 4. Host compiler RV32 emit path

Prefer **one binary, two backends** — not a second tree:

```text
holyc-riscv [--target rv64|rv32] file.hc -o out.bin
# default remains rv64
```

Or env / `#exe` define: `HOLYC_XLEN=32`. Smokes and linker scripts pass the flag
explicitly.

### Current host surface (where work lands)

| Path | Role today |
|------|------------|
| `host/parser.c` | Parse → IC; pointer/`sizeof` assumptions; inline `asm{}` encode helpers (`RvLoad`, …) |
| `host/compiler.c` / `host/compiler_helper.c` | AOT emit / IC lower |
| `host/holyc_compiler.h` | IC opcodes, AOT state |
| `host/holyc_fmt.c` | `--fmt` (gofmt-style; not an emit blocker) |
| `host/lexer.c`, `host/hash_table.c`, `host/main_stub.c` | Shared |

### Work items

| Area | RV64 today | RV32 change |
|------|------------|-------------|
| Load/store | `ld`/`sd` | `lw`/`sw`; `I64` → two `lw`/`sw` or helpers |
| Immediates | 64-bit lui/addi sequences | 32-bit; soft `I64` const materialization |
| Pointer arithmetic | ×8 scales often implicit | ×4 for pointers; keep ×8 for `I64*` |
| `sizeof` / `RT_*` | ptr = 8 | ptr = 4 when `XLEN==32` |
| Inline asm | `ld`/`sd` accepted | Accept `lw`/`sw`; reject or rewrite `ld`/`sd` on rv32 |
| Relocs / link | `tests/exec/harness/link_*.ld` @ `0x80000000` | Same map on virt-rv32 |
| Optional verify | `riscv64-unknown-elf-*` | `riscv32-unknown-elf-*` for objdump only |

### Explicit non-work

Do **not** fork `host/parser.c`. Introduce a small `holyc_target.h` (or equivalent
fields on the compiler object): `XLEN`, `PTR_BYTES`, stack align, ABI name —
and gate call sites.

Host AOT can keep emitting raw machine words (as today). Add `link_rv32.ld`
(or parameterized `OUTPUT_ARCH`) only if the exec harness still wraps blobs with
`riscv32-unknown-elf-gcc`.

## 5. Guest `Compiler_RV32` / dual emit

RV64 guest path is the **green** language destination ([COMPILER_RV.md](COMPILER_RV.md)):
`Compiler_RV.PRJ` → host-packed `Compiler.BIN`; phase3 proves `ExePutS`, guest
`Cmp` → BIN → Load → Call, and StartOS subset module Loads. **Do not start RV32
guest emit until that RV64 story stays green** (see §9).

Two shapes — choose at **P3**, not P0:

| Approach | Pros | Cons |
|----------|------|------|
| **`Compiler_RV32.PRJ`** + `Back*_RV32.HC` | Clear fork; RV64 stays green | Drift; double maintenance |
| **Dual emit in `Back*_RV.HC`** gated by `RV_XLEN` | One project | Larger diffs; easier to break RV64 |

**Recommendation:** keep RV64 `Compiler_RV.PRJ` pristine through P2. At P3,
start with **`#ifdef RV_XLEN_32`** (or Kconfig `CONFIG_ARCH_RISCV32`) inside
emit helpers (`lw`/`sw` vs `ld`/`sd`, `add` vs `addiw`) and only split files if
ifdef soup wins. Ship separate `Compiler_RV32.BIN` artifacts; never reuse RV64
BINs.

`Asm_RV.HC` / `AsmInit` need XLEN-aware encodings. Register *numbers* in
`RISCVRegs.HH` stay the same; spill slot width and `ICMov` paths change.

`make kernel-phase3-smoke` remains **RV64-only** until an explicit
`kernel-phase3-rv32-smoke` exists.

## 6. Kernel: trap frame, drivers, image size

### Trap / boot

Today’s thin trap path (`bootstrap/seed/trap.hc`) is **RV64-shaped**:

- 144-byte frame (`addi sp, sp, -144`)
- `sd` / `ld` of `ra`, temps, `a0`–`a7`, `s0`
- host slot load of trapvec via `ld`
- `mret` unchanged in meaning

RV32 needs a **half-width** frame (or an XLEN-parameterized one): `sw`/`lw`,
smaller `sp` adjust, and any trapvec that assumes 8-byte GPR snaps / fixed-area
layouts must match (the seed/`hc_repl` trap paths — the C trapvec that used to share
this layout went away with `worry_dream_repl.c`). Kernel paths that embed `ld`/`sd`
(e.g. `Kernel/KUtilsRV.HC` list/queue helpers) need the same gate.

`mtvec` direct mode remains fine for virt. Heap / `SYS_FIXED_AREA` bases come
from Kconfig — use **virt-scale DRAM** for kernel bring-up, not OpenTitan’s
128 KiB map.

### Drivers

Most `Kernel/Drv/*` MMIO drivers are largely width-agnostic at the register
level (UART 16550 byte MMIO; PLIC 32-bit MMIO). Still verify:

- CLINT `mtime` / `mtimecmp` are **64-bit MMIO** even on RV32 — already need
  two 32-bit accesses or soft `I64` (same as careful C on RV32).
- SiFive facade (`RVSifivePlat` / `RVSifiveYes|No`) — same API, still **RV64
  smoke first**; RV32 virt does not need SiFive for P0–P2.
- No accidental `ld`/`sd` in hand-written boot / trap asm under
  `CONFIG_ARCH_RISCV32`.
- `RVMemMap` / Man topics stay board-truthful; do not pretend OpenTitan is
  Kernel_RV.

`tests/exec/cases/kernel_plat_demo.hc` is the plat smoke shape to clone later
for virt-rv32 — still host-AOT + RV64 until P2.

### Image size vs OpenTitan

| Artifact (order of magnitude today) | Fits OpenTitan 128 KiB? |
|-------------------------------------|-------------------------|
| UART hello AOT blob | Yes (tiny-profile target) |
| REPL / seed subset | Maybe with aggressive strip |
| Kernel AOT / plat demos (~MB class with Compiler) | **No** |
| `Compiler_RV` blob (~1.1 MB) | **No** |
| Adam / DolDoc | **No** |

OpenTitan work is a **separate Kconfig profile**: stub or real Ibex UART, no
virtio/FB, no guest compiler, hard size budget in the smoke.

### Proposed Kconfig (implement when P0 starts — not now)

```text
choice ARCH
  ARCH_RISCV64   (default)
  ARCH_RISCV32
endchoice

# QEMU_SYSTEM default:
#   qemu-system-riscv32 if ARCH_RISCV32 || PLATFORM_OPENTITAN
#   qemu-system-riscv64 otherwise

# PLATFORM_OPENTITAN depends on / implies ARCH_RISCV32
```

Emit into `Kernel/RVAutoConf.HH`:

- `CONFIG_ARCH_RISCV32` / `RV_XLEN=32` / `RV_PTR_BYTES=4`

Defconfigs:

- `configs/virt_rv32_defconfig` — virt + `ARCH_RISCV32` + large DRAM defaults.
- Keep `opentitan_defconfig` experimental; document “not Kernel_RV.”

## 7. Phased milestones (P0–P4)

Do **not** add RV32 to default `make ci` / `qemu-integration` until P0 is green
locally. Host `make test` / compliance / `fmt-*` stay **RV64-only**.

### P0 — UART hello (bring-up)

**Work:** `holyc-riscv --target rv32` emits ILP32 for a ~20-line program; link
into QEMU virt-rv32; 16550 putc works.

**Success criteria:**

- Scripted smoke greps a fixed string on the UART within a timeout
  (`make kernel-rv32-hello-smoke` or `tests/scripts/run_rv32_uart_smoke.sh`).
- No RV64-only ops in the blob (`ld`/`sd`/`addiw` misuse caught by objdump or a
  tiny checker).
- Default RV64 path unchanged (`make test` still green).

### P1 — REPL / exec subset

**Work:** pointer ops, calls (≤8 args), soft `I64` add/sub/shift used by the
subset; host-AOT a small slice **without** expanding `jit.hc`.

**Success criteria:**

- Documented N exec-oracle cases pass on `qemu-system-riscv32 -M virt`.
- `I64` arithmetic smoke (values > 2³²) passes.
- Explicit skip list for `F64` / DolDoc / asm-heavy demos.

### P2 — Kernel slice on virt-rv32

**Work:** XLEN-aware trap frame + boot path; UART + CLINT under
`ARCH_RISCV32`; reduced PRJ or feature gates so the image “boots and ticks,”
not full Adam.

**Success criteria:**

- `make kernel-plat-rv32-smoke` (name TBD) prints PASS and survives a timer
  interrupt return.
- Struct/pointer size assumptions documented for touched headers.
- Still **not** OpenTitan.

### P3 — Guest compiler RV32 emit

**Work:** `ExePutS` of a fun-def returns a known value under guest Cmp on RV32
virt (same philosophy as RV64 phase3).

**Success criteria:**

- Guest-produced blob runs; host-produced `Compiler_RV32` seed only as bootstrap.
- RV64 `make kernel-phase3-smoke` remains green.

### P4 — OpenTitan tiny profile (optional)

**Work:** Ibex UART HolyC driver; size-capped hello; Kconfig DRAM 128 KiB.

**Success criteria:**

- `qemu-system-riscv32 -M opentitan` prints hello with the QEMU-supported boot
  story for that machine (`-bios none` or as documented then).
- CI optional; never block RV64.

### Stretch (not scheduled)

Adam subset, FB/Gr, virtio, soft `F64` or RV32D, sifive_u-on-rv32, dual-arch
nightly matrix — only after P2 is boring.

### CI / packages (when ready)

| When | What |
|------|------|
| P0 | Optional local smoke; document `qemu-system-riscv32` |
| P1 | Slice of `tests/exec` with `--target rv32` |
| P2 | Plat-style smoke on virt-rv32 |
| P3+ | Optional CI job `rv32-smoke` (`continue-on-error` until stable) |

Regression honesty: a failing RV32 job must not be hidden inside an otherwise
green RV64 `qemu-integration` until trusted — dedicated job or clearly named
target outside the default matrix.

## 8. Risks and dependencies on green RV64 work

### Dependencies (do not thrash these)

| RV64 baseline | Why RV32 depends on it |
|---------------|------------------------|
| `make` / `make test` / `make ci` (compliance + fmt + qemu-integration) | Shared host sources; regressions burn the port |
| `make kernel-plat-smoke` (+ sifive_u smoke when touching Drv) | Driver / Kconfig patterns RV32 will copy |
| `make kernel-phase3-smoke` | Guest Cmp is the P3 template; keep RV64 phase3 honest |
| `make repl-smoke` / `repl-regression` | Trap, UART, seed layout assumptions |
| `make fmt-check` / `fmt-test` | HolyC under enforced roots stays gofmt-clean while gated |
| SiFive / `RVMemMap` / Man topics | Board language stays coherent; do not invent a parallel C driver stack |

### Risks

| Risk | Why it hurts | Mitigation |
|------|--------------|------------|
| **`I64` everywhere** | Soft 64-bit ops bloat code and complicate ABI | Freeze pair ABI in P0; helpers for mul/div; measure size on P1 |
| **Pointer width vs TempleOS** | Struct offsets, `INVALID_PTR`, hash keys, “I64 as pointer,” REPL host slots | Layout audit; forbid loading RV64 BINs; ptr-vs-I64 cast discipline |
| **Shared emit ifdefs** | Dual-emit in `Back*_RV` breaks RV64 phase3 | Default arch RV64; dual-emit behind flag; keep phase3 green every PR |
| **Trap frame / fixed area** | 144-byte `sd` frame and 8-byte slot strides are baked into seeds + C guest | Parameterize early; do not “half-port” trap only |
| **JIT / heap size** | REPL and Cmp assume large heaps; OT has 128 KiB | Separate tiny profile; virt-rv32 for real work |
| **DolDoc / Adam** | Pointer-dense, graphics-era | Explicit non-goal until stretch |
| **Existing BINs are RV64** | Silent Load → illegal insn / wild jump | Arch tag or `*.rv32.bin` names |
| **F64** | RV32D optional; soft-float heavy | Skip until integer stack is solid |
| **Two QEMU binaries in CI** | Package / image cost | Optional job; document apt/brew names |
| **`hc_repl` / `jit.hc`** | Temptation to “just add RV32 JIT” | Freeze; host AOT or guest Cmp only |
| **OpenTitan mistaken for MVP** | 128 KiB + stub UART looks like a target but blocks Kernel | Virt first; OT = P4 |
| **In-flight RV64 platform work** | Uncommitted Drv / AutoConf / phase3 churn (e.g. SiFive plat) | Land/stabilize RV64 board work before opening RV32 emit PRs |

## 9. Explicit “do not start until…” gates

Do **not** open RV32 implementation PRs until **all** of the following hold:

1. **RV64 CI baseline is green** on the branch you branch from:
   `make ci` (or at least compliance + `fmt-check` + the qemu-integration slice
   that includes `kernel-plat-smoke` and `kernel-phase3-smoke`).
2. **No half-finished arch fork** — `ARCH_RISCV32` is not partially wired into
   default `virt` / `qemu-integration` in a way that can fail CI for everyone.
3. **ABI decision frozen in this doc** (already: ILP32 + wide `I64` + even–odd
   pairs) — do not reopen during P0.
4. **P0 is virt-rv32 only** — refuse “we’ll prove ABI on OpenTitan first.”
5. **Guest Cmp dual-emit (P3) waits** until P2 trap/UART/CLINT smoke is green
   **and** RV64 `kernel-phase3-smoke` is still green on the same tip.
6. **Formatter / seed churn** — if a PR is mid-flight on `bootstrap/seed/` trap
   layout or `Kernel/Drv/` SiFive API, finish or isolate that before stacking
   XLEN conditionals on the same lines.
7. **User/request gate** — this file is the plan; **implementation starts only
   when explicitly requested** (and preferably as a series of small PRs in the
   order in §10).

If any gate fails mid-port: **stop RV32 emit**, restore RV64 green, then resume.

5. Trap/boot width fixes behind `#ifdef CONFIG_ARCH_RISCV32`.
6. Only then: guest compiler emit and OpenTitan UART.

Do not land as one megadiff.

## 11. Decision summary

| Decision | Choice |
|----------|--------|
| First machine | **QEMU virt, riscv32** |
| OpenTitan | Later tiny profile (P4), not MVP |
| ABI | **ILP32**, pointers 32-bit |
| `I64` | Remains **64-bit** (soft ops / reg pairs) |
| Host compiler | Same `holyc-riscv` under `host/`, `--target rv32` |
| Guest compiler | After kernel slice; prefer gated emit, then split PRJ if needed |
| CI | RV64 default near-term; RV32 optional smoke when P0 green |
| TempleOS parity | **Not** a near-term goal on RV32 |
| `jit.hc` / Mac `hc_repl` | **Do not grow** for RV32 |
