# RISC-V 32-bit (RV32) port plan

Honest, actionable plan for an **RV32 / ILP32** fork of TempleOS/RV.
Today the tree is **RV64 / LP64** end-to-end (`holyc-riscv` AOT, `Compiler_RV`,
`Kernel_RV`, QEMU `virt`). The `opentitan` defconfig already picks
`qemu-system-riscv32` — that is **board scaffolding only**, not an RV32 ABI.

Status of this document: **planning**. Do not treat any milestone as started
until its success criteria land in CI or an explicit smoke target.

Related: [PLATFORM.md](PLATFORM.md) · [KCONFIG.md](KCONFIG.md) ·
[COMPILER_RV.md](COMPILER_RV.md) · [../docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md) ·
[../docs/RISCV_PORT_PLAN.md](../docs/RISCV_PORT_PLAN.md) (RV64 / self-host roadmap).

## 1. Goals / non-goals

### Goals (ordered)

1. **P0 bring-up:** a tiny AOT HolyC program prints over UART on
   **`qemu-system-riscv32 -M virt`** (same 16550/CLINT/PLIC map as RV64 virt).
2. **P1 language slice:** host `holyc-riscv` emits correct ILP32 codegen for the
   exec-oracle / REPL subset already trusted on RV64 (ints, calls, pointers,
   loops) — with `I64` as a real 64-bit type via soft ops.
3. **P2 kernel slice:** a reduced `Kernel_RV32` (or gated `Kernel_RV`) boots,
   traps, and returns from a timer/UART path on RV32 virt with enough RAM
   (default QEMU virt memory, not OpenTitan’s 128 KiB).
4. **P3 guest compiler (optional later):** `Compiler_RV32` or dual-emit
   `Compiler_RV` that produces RV32 machine code for `ExePutS` / `Cmp`.
5. **OpenTitan / Ibex (separate track):** a **tiny profile** (UART hello + maybe
   a few KiB of HolyC) once RV32 virt works — not a TempleOS host.

### Non-goals (near term)

- Full TempleOS / Adam / DolDoc / graphics parity on RV32.
- Replacing RV64 as the CI default or “supported” platform.
- Fitting `Kernel_RV.PRJ` (~1 MB+ AOT blobs) or `Compiler.BIN` (~1.1 MB) into
  OpenTitan’s **128 KiB** DRAM.
- Binary compatibility with existing RV64 `.BIN` / exec harness ELFs.
- Growing `bootstrap/hc_repl/jit.hc` for RV32 (same freeze rule as RV64).
- Shipping RV32 soft-float / RV32D as a first milestone (integer + soft `I64`
  first; `F64` after).

### First board: virt-rv32, not OpenTitan

| Target | Why |
|--------|-----|
| **`qemu-system-riscv32 -M virt`** | Same MMIO as RV64 virt (16550 @ `0x10000000`, CLINT, PLIC). Drivers already HolyC. DRAM is large. Isolates **ABI/codegen** from **tiny-RAM**. |
| **OpenTitan** | Valid *later* stress test (Ibex UART driver, 128 KiB budget, no CLINT). Wrong as the first ABI proving ground. |
| **sifive_e (rv32)** | ~16 KiB DTIM — worse than OpenTitan for anything beyond bare asm hello. |

Recommendation: add **`ARCH_RISCV32` + `virt` rv32 defconfig** when P0 starts;
keep `opentitan` as experimental and explicitly “tiny profile only.”

## 2. ABI and HolyC language model

### Current (RV64)

- **LP64:** pointers and `I64` are 8 bytes; codegen uses `ld`/`sd`, `addi` on
  64-bit GPRs; args in `a0`–`a7`, return in `a0`.
- Host parser hard-codes “pointers are 64-bit” in places (e.g. `host/parser.c`
  treating pointer types as `RT_I64`).
- Guest `Back*_RV.HC` / `Asm_RV.HC` / `RISCVRegs.HH` assume XLEN=64.

### Proposed RV32 default: **ILP32 + wide `I64`**

| Type | Size / align | Notes |
|------|----------------|-------|
| `I8`/`U8`/`I16`/`U16`/`I32`/`U32` | natural | Unchanged |
| **Pointers / `U8 *`** | **4 / 4** | ILP32; `sizeof(U8*)==4` |
| **`I64` / `U64`** | **8 / 8** (or 8/4) | Keep TempleOS meaning; implement with **two GPRs or libcalls** |
| `F64` | 8 | Soft-float or RV32D later; not P0 |

**Rationale:** TempleOS HolyC is `I64`-centric (loops, hash, dates, many APIs).
Shrinking `I64` to 32-bit would fork the language and break nearly every
portable `.HC` file. Keeping `I64` wide while shrinking pointers matches normal
C on RV32 and is the least-wrong TempleOS mapping.

### Rejected / deferred alternatives

| Option | Verdict |
|--------|---------|
| **I32-centric subset** (`I64` forbidden or = `I32`) | Only for a throwaway tiny demo. Do not call it TempleOS/RV. |
| **“LP64 on RV32”** (pointers still 8 bytes, high half zero) | Wastes RAM/regs; fights hardware; avoid. |
| **Soft-float as P0** | Defer; integer UART hello first. |

### Calling convention (sketch)

Follow the standard **ILP32** RISC-V psABI where practical:

- Args in `a0`–`a7`; 64-bit values occupy **even–odd** pairs (`a0`/`a1`, …) or
  are passed by reference if that matches the chosen soft-`I64` strategy —
  **pick one scheme in P0 and freeze it** (recommend: aligned register pairs,
  same as GCC `-mabi=ilp32` for `long long`).
- Callee-saved set same register names as RV64; stack aligned to **16 bytes**
  (psABI) even though XLEN=32.
- Trap frame: 32× **32-bit** GPRs + `mepc`/`mcause`/`mtval` (not 64-bit slots).

### Struct layout / TempleOS hazard

Many kernel/Adam structs were written assuming **8-byte pointers** and
`sizeof(I64)==8` with no padding surprises. On ILP32:

- Every pointer member shrinks → **offsets change**.
- Packed “I64 holding a pointer” patterns need audit (`INVALID_PTR`, hash
  entries, `CTask *`, DolDoc pointers).
- Existing **AOT BINs and `Compiler.BIN` are RV64** — never Load them on RV32.

**Success gate before Kernel_RV32:** a short “layout ABI” doc or `#assert`-style
checks for a handful of critical structs (`CTask`, hash nodes, `CHashTable`)
under both widths, or `#ifdef` / size macros until layouts converge.

## 3. Host compiler (`holyc-riscv`)

### Target surface

Prefer **one binary, two backends** over a second tree:

```text
holyc-riscv [--target rv64|rv32] file.hc -o out.bin
# default remains rv64
```

Or env/`#exe` define: `HOLYC_XLEN=32`. Linker scripts and smoke Makefiles pass
the flag explicitly.

### Work items

| Area | RV64 today | RV32 change |
|------|------------|-------------|
| Load/store | `ld`/`sd` | `lw`/`sw`; `I64` → two `lw`/`sw` or helper |
| Immediates | 64-bit lui/addi sequences | 32-bit; `I64` const materialization |
| Pointer arithmetic | ×8 scales often implicit | ×4 for pointers; keep ×8 for `I64*` |
| `sizeof` / `RT_*` | ptr = 8 | ptr = 4 when `XLEN==32` |
| Inline asm mnemonics | `ld`/`sd` accepted | Accept `lw`/`sw`; reject or rewrite `ld`/`sd` |
| Relocs / link | `tests/exec/harness/link_*.ld` @ `0x80000000` | Same map on virt-rv32; entry still DRAM base |
| Toolchain (optional verify) | `riscv64-unknown-elf-*` | `riscv32-unknown-elf-*` for objdump/link checks only |

### Assembler / linker

- Host AOT can keep emitting raw machine words (as today) — no mandatory
  external `as` for P0.
- Add **`link_rv32.ld`** (or parameterized `OUTPUT_ARCH(riscv)`) for exec
  harness ELFs built with `riscv32-unknown-elf-gcc` as the ELF wrapper if the
  harness stays C+blob.
- QEMU `-kernel` expects an ELF or raw image matching the board reset vector;
  virt-rv32 matches virt-rv64 link address conventions used by the harness.

### Explicit non-work

Do not dual-maintain a full second copy of `host/parser.c`. Gate width in a small
`holyc_target.h` (XLEN, PTR_BYTES, stack align, ABI name) and fix call sites.

## 4. Guest `Compiler_RV`

Two viable shapes — choose at P3, not P0:

| Approach | Pros | Cons |
|----------|------|------|
| **`Compiler_RV32.PRJ`** + `Back*_RV32.HC` | Clear fork; RV64 stays green | Drift; double maintenance |
| **Dual emit in `Back*_RV.HC`** gated by `RV_XLEN` | One project | Larger diffs; easier to break RV64 |

**Recommendation:** keep RV64 `Compiler_RV.PRJ` pristine through P2. At P3,
start with **`#ifdef RV_XLEN_32`** inside emit helpers (load/store/addiw vs add)
and only split files if the ifdef soup wins. Ship separate `Compiler_RV32.BIN`
artifacts; never reuse RV64 BINs.

`Asm_RV.HC` / `AsmInit` instruction tables need XLEN-aware encodings (`LW`/`SW`,
no `LD`/`SD`, `AUIPC`+`JALR` still fine). `RISCVRegs.HH` register *numbers*
stay the same; only spill slot width and `ICMov` paths change.

## 5. Kernel

### Boot / traps

- `KBootRV` / trap entry: save/restore **32-bit** GPRs; `mret` unchanged.
- `mtvec` direct mode is fine for virt.
- Stack pointer and `SYS_FIXED_AREA` / heap bases from Kconfig — same as RV64
  virt once DRAM size is large; **do not** reuse OpenTitan’s 128 KiB map for
  kernel bring-up.

### Drivers

Most `Kernel/Drv/*` MMIO drivers are width-agnostic (UART 16550, CLINT
`mtime` is 64-bit MMIO even on RV32 — already two 32-bit accesses or a
`U64` load). Verify:

- CLINT `mtime`/`mtimecmp` **64-bit** accesses on RV32 (two `lw`/`sw` or soft
  `I64`).
- PLIC register width (32-bit MMIO — already).
- No accidental `ld`/`sd` in hand-written boot asm.

### Image size vs OpenTitan

| Artifact (order of magnitude today) | Fits OpenTitan 128 KiB? |
|-------------------------------------|-------------------------|
| UART hello AOT blob | Yes (target for tiny profile) |
| REPL / seed subset | Maybe with aggressive strip |
| `Kernel_RV.PRJ` AOT (~1 MB class) | **No** |
| `Compiler_RV` blob (~1.1 MB) | **No** |
| Adam / DolDoc | **No** |

OpenTitan work is a **separate Kconfig profile**: stub PLIC or minimal, Ibex
UART driver, no virtio/FB, no guest compiler, hard size budget in the smoke.

## 6. QEMU targets and Kconfig

### Machines (rv32 QEMU 10.x)

| `-M` | Role for this plan |
|------|--------------------|
| **virt** | **Primary** RV32 bring-up + CI slice |
| opentitan | Tiny profile only; Ibex UART TBD |
| sifive_u / spike / amd_microblaze_v | Optional later; same ABI as virt-rv32 |
| sifive_e | Ignore until sub-32 KiB demos exist |

### Proposed Kconfig shape (implement when P0 starts)

```text
choice ARCH
  ARCH_RISCV64   (default)
  ARCH_RISCV32
endchoice

# QEMU_SYSTEM default:
#   qemu-system-riscv32 if ARCH_RISCV32 || PLATFORM_OPENTITAN
#   qemu-system-riscv64 otherwise

# PLATFORM_OPENTITAN implies ARCH_RISCV32 (or depends on it)
```

Emit into `Kernel/RVAutoConf.HH`:

- `CONFIG_ARCH_RISCV32` / `RV_XLEN=32` / `RV_PTR_BYTES=4`

Defconfigs:

- `configs/virt_rv32_defconfig` — virt + `ARCH_RISCV32` + large DRAM defaults.
- Keep `opentitan_defconfig` experimental; document “not Kernel_RV.”

`make qemu-args` already switches binary for OpenTitan; extend that for all
`ARCH_RISCV32` platforms.

## 7. Testing / CI

Do **not** add RV32 to the default `make ci` matrix until P0 is green locally.

| When | What |
|------|------|
| P0 | Manual / optional `make kernel-rv32-hello-smoke` (or `tests/scripts/run_rv32_uart_smoke.sh`) using `qemu-system-riscv32 -M virt` |
| P1 | Slice of `tests/exec` cases recompiled with `--target rv32` (start with `e_for_sum`, pointer demos — skip F64) |
| P2 | `kernel-plat` style smoke on virt-rv32 (UART + CLINT tick) |
| P3+ | Optional CI job `rv32-smoke` behind `qemu-system-riscv32` availability; `continue-on-error` until stable |

Host `make test` / compliance stay **RV64-only**. Document required packages:
`qemu-system-riscv32` (and optionally `riscv32-unknown-elf-gcc`).

Regression honesty: one failing RV32 job must not be hidden by RV64 green —
either a dedicated job or a clearly named target outside `qemu-integration`
until trusted.

## 8. Phased milestones

### P0 — UART hello (bring-up)

**Work:** `holyc-riscv --target rv32` emits ILP32 for a 20-line program; link
into QEMU virt-rv32; 16550 putc works.

**Success criteria:**

- Scripted smoke greps a fixed string on the UART within a timeout.
- No RV64 instructions in the blob (`ld`/`sd`/`addiw` misuse caught by
  objdump or a tiny checker).
- Default RV64 path unchanged (`make test` still green).

### P1 — REPL / exec subset

**Work:** pointer ops, calls (≤8 args), `I64` soft add/sub/shift used by the
subset; port or gate a minimal bootstrap seed **or** host-AOT a small REPL
slice — without expanding `jit.hc`.

**Success criteria:**

- N exec-oracle cases (document the list) pass on `qemu-system-riscv32 -M virt`.
- `I64` arithmetic smoke (values > 2³²) passes.
- Explicit skip list for `F64` / DolDoc / asm-heavy demos.

### P2 — Kernel slice on virt-rv32

**Work:** trap frame, `KBootRV` path, UART + CLINT under `ARCH_RISCV32`;
reduced PRJ or feature gates so image is “boots and ticks,” not full Adam.

**Success criteria:**

- `make kernel-plat-rv32-smoke` (name TBD) prints PASS and survives a timer
  interrupt return.
- Struct/pointer size assumptions documented for touched headers.
- Still **not** OpenTitan.

### P3 — Guest compiler RV32 emit

**Work:** `ExePutS` of a fun-def returns a known value under guest Cmp on RV32
virt (mirror phase3 philosophy on RV64 — see [COMPILER_RV.md](COMPILER_RV.md)).

**Success criteria:**

- Guest-produced blob runs; host-produced `Compiler_RV32` seed only as bootstrap.
- RV64 phase3 smokes remain green.

### P4 — OpenTitan tiny profile (optional)

**Work:** Ibex UART HolyC driver; size-capped hello; Kconfig DRAM 128 KiB.

**Success criteria:**

- `qemu-system-riscv32 -M opentitan` prints hello with `-bios none` (or the
  QEMU-supported boot story for that machine).
- CI optional; never block RV64.

### P5+ — Stretch (not scheduled)

Adam subset, FB/Gr, virtio, soft `F64` or RV32D, sifive_u rv32, dual-arch
nightly matrix. Only after P2 is boring.

## 9. Risks

| Risk | Why it hurts | Mitigation |
|------|--------------|------------|
| **`I64` everywhere** | Soft 64-bit ops bloat code and complicate calling convention | Freeze pair ABI early; helpers for mul/div; measure code size on P1 |
| **Pointer width vs TempleOS** | Struct offsets, `INVALID_PTR`, hash keys, “I64 as pointer” | Layout audit; forbid loading RV64 BINs; ptr-vs-I64 cast warnings |
| **JIT / heap size** | REPL and Cmp assume large heaps; OpenTitan has 128 KiB | Separate tiny profile; virt-rv32 for real work |
| **DolDoc / Adam** | Huge, pointer-dense, graphics-era | Explicit non-goal until P5 |
| **Existing BINs are RV64** | Silent Load → illegal instruction / wild jump | Magic/header arch tag or separate `*.rv32.bin` names |
| **RV64 regressions** | Shared `Back*_RV` ifdefs | Default arch RV64; CI stays RV64-first; dual-emit behind flag |
| **F64** | RV32D optional; soft-float heavy | Skip until integer stack is solid |
| **Two QEMU binaries in CI** | Image size / package availability | Optional job; document apt/brew package names |
| **hc_repl / jit.hc** | Temptation to “just add RV32 JIT” | Freeze; host AOT or guest Cmp only |
| **OpenTitan mistaken for MVP** | 128 KiB + stub UART looks like a target but blocks Kernel | Plan: virt first; OT last |

## 10. Suggested first patches (when implementation starts)

Order of landing, each small and reviewable:

1. **Docs only** — this file + Kconfig comments (done by the plan).
2. **`ARCH_RISCV32` stub** in Kconfig + `virt_rv32_defconfig` + `QEMU_SYSTEM`
   default (no codegen yet).
3. **`holyc_target` XLEN=32** with `lw`/`sw` and soft `I64` add/mov for a
   single `tests/exec` case.
4. **`run_rv32_uart_smoke.sh`** + Makefile target.
5. Trap/boot width fixes behind `#ifdef CONFIG_ARCH_RISCV32`.
6. Only then: guest compiler emit and OpenTitan UART.

No commit is required to keep this plan useful; implementation should not land
as one megadiff.

## 11. Decision summary

| Decision | Choice |
|----------|--------|
| First machine | **QEMU virt, riscv32** |
| OpenTitan | Later tiny profile, not MVP |
| ABI | **ILP32**, pointers 32-bit |
| `I64` | Remains **64-bit** (soft ops / reg pairs) |
| Host compiler | Same `holyc-riscv`, `--target rv32` |
| Guest compiler | After kernel slice; prefer gated emit, then split PRJ if needed |
| CI | RV64 default forever near-term; RV32 optional smoke when P0 green |
| TempleOS parity | **Not** a near-term goal on RV32 |
